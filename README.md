# Telegram-бот для многоязычных рассылок

Небольшой сервис на PHP 8.4 и SQLite. Администратор отправляет боту обычный текст; бот переводит его через DeepL и рассылает подписчикам на выбранном языке. Все действия выполняются в личном чате Telegram.

## Возможности

- Открытая регистрация: язык → имя → компания → страна → телефон.
- Языки: русский (`RU`), британский английский (`EN-GB`), испанский (`ES`), французский (`FR`). Вопросы регистрации и служебные сообщения переведены заранее.
- Телефон через кнопку своего контакта или ручной ввод `+447700900123`. Пробелы, скобки и дефисы допускаются; проверяется формат, без SMS.
- Незавершённая регистрация продолжается после перезапуска.
- При первой регистрации пользователь получает последнюю готовую рассылку, если она существует. Повторный `/start` её не отправляет.
- `/language` меняет язык следующих рассылок; `/stop` отключает подписку; `/start` возвращает подписку; `/help` показывает справку.
- Администраторы определяются по числовым Telegram ID из конфигурации. Они не проходят регистрацию и автоматически не подписываются.
- Любой новый обычный текст администратора сразу запускает отдельную рассылку, **без подтверждения**. Бот отвечает номером и числом получателей, затем итогами отправки.
- `/retry ID` повторяет только неуспешные задания указанной рассылки.

Команды, редактирование сообщений, сообщения в группах, фотографии, документы и подписи к вложениям не создают рассылок. В первой версии нет чата поддержки, поиска материалов, административной веб-панели или истории для просмотра пользователем. Текст отправляется без Markdown/HTML-оформления; абзацы сохраняются.

## Устройство проекта

| Часть | Ответственность |
|---|---|
| `src/Application` | Регистрация, роли, команды, перевод и доставка. Интерфейсы внешних зависимостей. |
| `src/Domain` | Правила деления текста и классификация ошибок API. |
| `src/Infrastructure` | SQLite, Telegram, DeepL, HTTP, консольный запуск, блокировки и резервные копии. |

`Kernel` принимает Telegram update и в одной транзакции сохраняет его идентификатор, изменения анкеты и задания. Повторный update не создаёт повторную рассылку. `Poller` использует сохранённое смещение для long polling.

`Worker` берёт по одному заданию из SQLite. На каждый язык рассылки существует один перевод. Сначала готовы все переводы для исходной аудитории, затем разрешается доставка. При регистрации нового пользователя недостающий перевод последней готовой рассылки создаётся отдельно.

Аудитория и языки фиксируются при создании рассылки. Перед каждой отправкой снова проверяется подписка. Успешные фрагменты длинных сообщений записываются отдельно, поэтому повтор продолжает доставку с неотправленного фрагмента.

Временные ошибки повторяются с увеличением задержки, максимум пять попыток на операцию. Telegram `retry_after` задаёт нижнюю границу ожидания. Блокировка бота отключает подписку. Ошибки ключа или квоты DeepL завершают задание ошибкой и дают уведомление администратору. Исходный текст вместо отсутствующего перевода не отправляется.

«Отправлено» означает успешный ответ Telegram API, а не прочтение сообщения. При обрыве соединения после принятия сообщения Telegram возможен повтор: абсолютной гарантии «ровно один раз» у Bot API нет.

Зависимости в runtime: PHP, стандартные расширения, Composer autoload. SQLite работает в WAL-режиме. Одновременно запускается один `poll` и один `worker`; файловые блокировки защищают от случайного повторного запуска роли на общем томе. Масштабирование на несколько серверов не предусмотрено.

## Конфигурация

Скопируйте `.env.example` в `.env` и заполните значения **локально**, не публикуя токены.

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота из BotFather. |
| `TELEGRAM_ADMIN_IDS` | Положительные числовые Telegram ID через запятую без пробелов: `123456789,987654321`. |
| `DEEPL_API_KEY` | Ключ именно DeepL API. |
| `DEEPL_API_URL` | `https://api-free.deepl.com` или `https://api.deepl.com`, согласно тарифу ключа. |
| `DATABASE_PATH` | Локально `./var/broadcast.sqlite`. В Compose всегда `/data/broadcast.sqlite`. |

Пользователь должен сам открыть бота и нажать «Старт». Администратор тоже сначала открывает личный чат. Для long polling у бота не должно быть активного webhook; используйте нового тестового бота или отключите ранее настроенный webhook перед переключением.

Ключи не попадают в Docker-образ. `.env`, база данных и `vendor` исключены из контекста сборки. Приложение читает переменные окружения; встроенного загрузчика `.env` нет. Compose загружает файл сам.

## Локальный запуск и тесты

Требуется PHP 8.4+ с `curl`, `mbstring`, `pdo_sqlite`, `sqlite3`; для PHPUnit также стандартные XML/DOM-расширения. На Linux для штатной остановки процессов установите `pcntl`. В контейнере эти расширения предусмотрены.

```bash
composer install
composer test
```

В Linux после заполнения собственного `.env` экспортируйте его переменные:

```bash
set -a
. ./.env
set +a
php bin/console migrate
```

В двух терминалах с одинаковым окружением:

```bash
php bin/console poll
```

```bash
php bin/console worker
```

В PowerShell переменные задаются через `$env:ИМЯ = 'значение'` в каждом терминале. Пример пути базы: `$env:DATABASE_PATH = "$PWD/var/broadcast.sqlite"`.

`php bin/console help` показывает команды. `worker --once` выполняет один проход, `poll --once` — один запрос updates без длинного ожидания. Эти режимы работают с реальными API при наличии заданий; для проверки без отправок используйте пустую отдельную базу.

Тесты используют настоящую временную SQLite и подменяют внешние API. Покрыты регистрация, роли, языки, подписки, дедупликация, переводы, ошибки, повторная доставка, очередь, конфигурация, блокировки и резервное копирование.

## Docker и сервер

Нужны Linux, Docker Engine и Docker Compose. Публичные порты и домен не требуются. Контейнерам нужен исходящий HTTPS к Telegram и DeepL.

Из каталога проекта сначала проверьте тестовую сборку, затем соберите рабочую:

```bash
docker build --target test -t telegram-broadcast:test .
docker compose build
docker compose run --rm poll migrate
docker compose up -d
docker compose logs --tail=100 -f
```

Оба сервиса используют один образ и постоянный именованный том `bot-data`. Процессы работают от UID 1000, перезапускаются автоматически, обрабатывают SIGTERM. Worker ограничивает темп до одного прохода примерно за 1,1 секунды. Остановка Compose даёт процессам 45 секунд для завершения текущего HTTP-вызова.

Логи — JSON в stdout: тип события, номер задания, номер попытки, результат обработки. Ошибки содержат класс исключения, без его исходного сообщения и стека. Анкеты, телефоны, ключи и полные тексты рассылок в логи не записываются. У Compose включена ротация журналов.

При `command_failed` проверьте заполнение всех переменных, положительные ID администраторов, доступность каталога базы, отсутствие второго процесса той же роли и правильный адрес DeepL. При `backup_failed` проверьте место на диске и права на том. Ошибки переводов дополнительно приходят администратору в Telegram.

Перед обновлением:

```bash
docker compose run --rm worker backup
docker compose stop
docker build --target test -t telegram-broadcast:test .
docker compose build
docker compose run --rm poll migrate
docker compose up -d
```

Сохраните каталог проекта и имя Compose-проекта при обновлении, чтобы использовать тот же том. `docker compose down` сохраняет данные; `down -v` удаляет том и данные.

## Резервные копии и восстановление

Worker создаёт согласованную копию через `SQLite3::backup` при первом проходе нового дня UTC. После перезапуска проверяет сохранённую отметку дня. Ошибка не отмечает копию успешной; повтор возможен через минуту. Проверяется `PRAGMA integrity_check`.

Копии находятся в `/data/backups/broadcast-YYYYMMDD-HHMMSS-microseconds.sqlite`. Хранятся семь дней; удаляются только файлы собственного формата, не рабочая база. Отдельная копия перед восстановлением сохраняется в `/data/backups/before-restore`.

Ручное копирование доступно при работающем сервисе:

```bash
docker compose run --rm worker backup
```

Копии в том же томе защищают от ошибок обновления, но не от потери диска сервера. Регулярно переносите готовые `.sqlite`-копии на отдельное хранилище средствами сервера.

Восстановление требует остановленных процессов и явного `--confirm`. Подставьте имя нужной копии:

```bash
docker compose stop
docker compose run --rm worker restore /data/backups/broadcast-YYYYMMDD-HHMMSS-microseconds.sqlite --confirm
docker compose run --rm poll migrate
docker compose up -d
```

Перед заменой существующей базы команда сохраняет её копию. Не удаляйте и не переносите активные SQLite/WAL-файлы вручную. Для локального запуска доступны те же `backup` и `restore` через `php bin/console`; этим командам нужна только `DATABASE_PATH`.

## Приёмка с настоящими API

Автоматические проверки не заменяют проверку ключей и качества переводов. До подключения клиентов:

1. Создайте отдельного тестового бота, заполните его токен, DeepL API-ключ и ID администратора.
2. Пройдите регистрацию тестовыми пользователями на четырёх языках; проверьте текст вопросов, телефон и продолжение незавершённой регистрации.
3. Отправьте администратором короткое объявление, затем типичное объявление с артикулами, ценами и датами. Проверьте переводы вручную и итоговый отчёт.
4. Зарегистрируйте нового пользователя: он получает последнюю готовую новость один раз.
5. Проверьте `/language`, `/stop`, повторный `/start` и отсутствие отправок отписавшемуся пользователю.
6. Перезапустите контейнеры с заданиями в очереди, проверьте продолжение обработки и резервную копию.

В этой поставке выполнены локальные автоматические проверки на PHP 8.4.25 и проверка консольного цикла с отдельной пустой базой. Docker-сборка, реальные Telegram/DeepL-вызовы и развёртывание требуют окружения и ключей; они здесь не выполнялись.

Документация API: [Telegram Bot API](https://core.telegram.org/bots/api), [DeepL Translate](https://developers.deepl.com/api-reference/translate/request-translation).
